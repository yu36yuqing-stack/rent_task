# rent_task 生产发布检查清单

仅在 `production-release` Skill 已满足发布授权条件后使用。

## 发布前

- 当前目录是 `rent_task` 项目根目录。
- 当前分支和目标分支已确认。
- 已检查 `git status` 和实际差异。
- 已区分代码改动与数据库、日志等运行态文件。
- 会被 `rsync --delete` 同步和宿主机 `git add` 提交的文件均属于本次发布。
- 重要未提交代码已保护，不会被脚本中的本机代码对齐步骤丢失。
- 本次改动对应测试已通过；核心业务改动符合行覆盖率 90% 要求。
- 数据库迁移已检查，未发现未验证或不可逆的高风险操作。
- 未把密码、令牌、数据库、日志或敏感配置加入待提交范围。

## 脚本阶段

`scripts/merge_code.sh` 当前包含以下五个阶段：

1. 将本机代码同步至生产宿主机，排除数据库、日志、覆盖率目录和敏感配置。
2. 在宿主机提交全部允许提交的变化并推送目标分支。
3. 执行数据库迁移，重启常驻服务并检查 `/api/ping`。
4. 将本机代码与远程目标分支对齐。
5. 将生产环境 `database/*.db` 和 `log/` 回拉到本机。

只有五个阶段全部完成且健康检查通过，才能报告“发布成功”。

## 结果分类

- **成功**：五个阶段全部完成，迁移和 `/api/ping` 正常，数据库与日志回拉完成。
- **部分完成**：生产代码或服务已更新，但推送、本机对齐、数据库回拉或日志回拉失败。
- **失败**：生产代码未完成同步或部署，或者无法确认生产环境状态。

## 发布报告

向用户报告以下内容：

- 结果：成功 / 部分完成 / 失败。
- 目标分支和最终提交。
- 发布前测试及覆盖率结果。
- 代码同步和仓库推送结果。
- 数据库迁移结果。
- 服务重启及 `/api/ping` 结果。
- 数据库和日志回拉结果。
- 本机最终工作区状态。
- 异常、未验证项及建议的下一步。
