# 钉钉状态汇报去重测试报告

## 测试范围

- 主状态汇报首次发送、内容未变化跳过、内容变化重发。
- 账号行字段级变化标记，包括在线状态、订单数、三平台状态、名称和提示。
- 商品主档新增、移除以及订单总数、主档总数等汇总变化标记。
- 标记文案不参与指纹，变化后的下一轮内容不变时继续跳过。
- 仅汇报时间或列表顺序变化时不重复发送。
- 钉钉群地址变化后强制发送。
- 钉钉发送失败后不记录成功指纹，下一轮继续重试。
- 指纹读取失败时放行发送；指纹保存失败不把已成功发送误判为失败。
- 不同用户之间的去重状态隔离。
- Telegram-only 和无通知配置的原有行为回归。
- 定时任务、手工同步后台任务在通知失败时保留渠道执行结果。

## 测试环境

- Node.js：项目当前本地运行时。
- 数据库：每个测试使用独立临时 SQLite 数据库，不读写生产数据。
- 外部通知：使用 stub，不调用真实钉钉或 Telegram 接口。

## 失败项与剩余风险

- 最终测试无失败项。
- 钉钉接口成功返回后、指纹写入前若进程被强制终止，下一轮可能重复发送一次；不会漏发。
- 运行任务仅保留 7 天。用户停用超过保留期后再次启用，第一轮会重新发送一次状态汇报。
- 上线前的历史任务只有指纹、没有结构化快照；首次发生变化时会正常发送但不标注字段，成功保存新快照后才开始精确标记。
- 更换钉钉群时视为新目标，会发送完整汇报但不标注旧群的历史变化。
- 本次只对商品状态主汇报去重；独立风控、投诉、黑名单和错误告警不去重。
