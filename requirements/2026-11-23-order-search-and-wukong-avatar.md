# 订单搜索样式与黑悟空头像

**状态：已批准，本地实现，未发布。**

## 背景和范围

订单搜索输入框沿用通用表单字号和内边距，明显高于旁边的按钮；空结果也继承了正文样式。黑悟空订单依赖悠悠图片，图片不可用时不容易从其他主机订单中认出。

- 订单搜索复用 ListSearch，搜索和清空按钮与同步订单使用同一套 PageAction 样式，不额外设置高度；输入框 34px 高、字号 14px，可略高于按钮且垂直居中。文字和占位提示用已有主题色，空结果使用既有说明文字样式。
- 主机订单中 `source_game_id=11001` 使用[Steam 社区的游戏头像](https://shared.fastly.steamstatic.com/community_assets/images/apps/2358720/764ad8ff458f7020d63a3f7f0abf6ad8882c05df.jpg)作为本地资源，直接显示，不依赖悬停或第三方图片请求。
- 不改搜索匹配、订单归属和收益口径，不改变板卡、定价和弹窗的输入控件。

## 验收

- 手机和桌面验证搜索、清空与同步订单的按钮样式一致；输入框垂直居中，空结果正常换行、不溢出。
- 黑悟空在 GTA6 订单列表直接显示头像；模拟渠道图片失效时仍能显示，其他游戏保留原有回退。
- 提交、回车、清空、空结果和请求失败行为不变。

## 测试结果

- 本地 Chromium，使用测试数据：320、390、1280px 三种宽度覆盖五个游戏标签，共 15 组。搜索、清空与同步订单按钮均为 29px，字号、颜色、圆角和内边距相同；输入框 34px，垂直居中。空结果以 12px 说明文字展示，窄屏正常换行。截图：`coverage/order-search/orders-search-empty-320.png`。
- `npm run test:order-search` 的 6 组回归通过。`npm run coverage:rental-device-orders` 通过，验证本地头像无需访问渠道图片、其他游戏保留图标回退，以及主机订单分页与统计不受影响。该命令覆盖已有主机订单服务、数据访问与迁移，行、分支、函数覆盖率分别为 99.13%、91.37%、100%。
- 本次 `menu_orders.js` 的可执行改动行覆盖 6/6；从改动行开始的分支覆盖 8/9，含改动的函数覆盖 2/2。旧搜索覆盖门槛仍因未改动的 `app_core.js`、`local_h5_server.js` 两处历史改动范围未达标而失败。明细：`coverage/order-search/scope-coverage.json`。
- 未验证真机 Safari；头像与样式均为本地资源和 CSS 变更，不涉及数据迁移。回滚时仅撤销本需求的 H5 改动、资源和缓存版本。
