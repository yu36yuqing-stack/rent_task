# 独立时租倍率实现与测试报告

- 日期：2026-10-25，Asia/Shanghai。
- 环境：macOS、Node.js 24、SQLite、c8、Puppeteer / Chrome。
- 需求：套餐比例设置开放原先固定为1的时租倍率。实际时租价等于原始基础时租价乘时租倍率；其他套餐仍使用原始基础时租价乘自身倍率，不连乘时租倍率。
- 范围：仅本地实现与验证，没有提交、发布生产或调用真实渠道写接口。测试使用隔离五库、模拟渠道接口和浏览器API拦截。

## 行为与改动范围

| 文件 | 实际变化 |
| --- | --- |
| `price/channel_package_ratio.js` | hour 不再强制归为1，支持大于0、四位小数归一化，缺省仍为1；非法倍率使用明确业务错误码 |
| `price/channel_adapters/uhaozu_price_adapter.js` | 配置倍率路径单独缩放时租，包夜/包天/包周仍从原始基价计算；旧版按现有渠道价格推导比例的兼容函数保持原语义 |
| `price/channel_adapters/uuzuhao_price_adapter.js` | 实际时租与其他八种套餐分别从原始基价计算 |
| `price/channel_adapters/zuhaowang_price_adapter.js` | 时租独立缩放；仅日租商品保留未缩放基价，不向其启用时租；接收实际租赁模式用于日租策略处理 |
| `price/daily_price_policy.js` | 跟随/持平/递减计算口径不变，时租不受日租系数折扣；仅日租不比较无效时租，仅时租不应用无效日租策略 |
| `price/package_ratio_service.js` | 显式新客户端标识才允许修改hour，旧页面保存其他套餐保留服务端原值；保存前按关联账号及租赁方式检查金额正值和既有日租冲突，再保存并入队 |
| `h5/local_h5_server.js` | 仅透传 `hour_ratio_editable`；非法倍率映射400，原并发版本冲突仍为409 |
| `price/price_ladder_reconcile_service.js` | 计算、签名、日志与发布输入分离原始 `base_hour_price` 和渠道实际hour；租号王透传计算时的缓存租赁模式 |
| `price/price_publish_service.js` | 租号王基价只用于内部快照和日志，不混入平台业务参数；最新模板模式发生变化时先安全中止，等待重新计算，禁止按旧模式价格提交 |
| `price/zuhaowang_price_snapshot_service.js` | 新日志和已应用签名使用明确基价恢复；旧数据缺省时兼容原 `target.hour`，显式非法或矛盾基价不回退伪造成功 |
| `database/zuhaowang_product_mode_db.js` | 新增窄范围数据访问方法，原子更新对应商品的租赁模式。按用户/游戏/账号/商品ID/原模式及有效状态保护，只改mode与修改时间，不覆盖并发价格、其他渠道或换绑后的商品 |
| `h5/public/js/menu_price.js` | 开放时租输入、草稿、校验、演算和提交；示例基价先规范化精度，其他套餐不连乘hour倍率；四档输入继续保存原始基价 |
| `h5/public/js/ui/daily_price_policy.js` | 明确原始基础价文案，并统一示例基价精度；原日租和关联套餐算法不变 |
| `h5/public/index.html`、`h5/COMPONENT_GUIDE.md` | 复用现有布局和组件，说明独立倍率，相关JS资源版本更新为20261025a |
| `package.json`、新增及既有相关测试 | 增加 `test:hour-ratio`、`test:hour-ratio-visual`、`coverage:hour-ratio`；沿用既有完整阶梯与商品价格回归 |

没有数据库结构变更或迁移。现有 `ratios_json.hour` 存储新倍率；旧配置仍为1，旧记录缺少hour时也按1兼容。

例如U号租原始基价2元、时租1.2倍、日租6倍，最终为2.40元/小时与12元/天，不是14.40元/天。保存不立即调用渠道，只将对应渠道账号入队；自动调价关闭时只保留配置，开启且同步条件满足后才处理。

### 用例分类

- 正常：三渠道倍率0.9/1/1.2、四档价格、保存和重载、明确重置回1、保存只入队及开启后发布；四游戏同号按身份隔离，不能通过请求体指定其他号主。
- 独立性：时租加成后，各非hour套餐仍等于原始基价乘自身倍率；三种日租策略、U号租包夜和悠悠短租关联折扣保持原口径。
- 精度：倍率四位归一化、渠道金额精度、租号王日租截断；示例2.123先归为2.12，再乘1.2得到2.54，3.255先归为3.25再得到3.90；预览与三个真实适配器交叉验证。
- 异常：非法/零/负倍率、精度归零、冲突套餐、400/401/409、保存失败、非法基价不伪造可信快照、失败不改变已确认价格。
- 兼容：旧客户端无编辑标识，即使提交hour=1也不能覆盖已有自定义值；新客户端可显式重置1；旧JSON、旧成功日志和旧已应用签名继续兼容。
- 租赁模式：租号王仅日租/仅时租/混合模式；缓存与最新模板之间全部六向变化；失效dataId叠加模式变化，下轮可恢复；并发修改价格不丢失，并发换绑不覆盖。
- 实际任务链：模式变化首轮零改价、仅CAS刷新模式；5分钟内不绕过原退避；31分钟后读取新模式、重新计算并成功发布。原始基价进入已应用签名，未缩放虚拟hour不能静默下发为真实时租。
- 前端：渠道草稿隔离、保存锁与重复提交保护、失败保留、实时普通文字结果；三渠道 × 跟随/持平/递减 × 0.9/1/1.2 × 320/375/390/430/768/1280px，共162例，另12例精度/归零。浏览器API全部fixture拦截，未发现意外请求或页面错误。

### 首轮发现与处理

- 日志增加基价与实际时租区分字段后，旧深比较断言需要同步；已更新预期，并补充非1倍率日志验证，未删除原金额断言。
- 独立复核发现缓存day_only切换为实际混合模式可能将未缩放hour错误提交。已补模板模式一致性保护、原子模式刷新及真实任务重试闭环；没有扩大或缩短渠道重试策略。
- 任务重试测试初版的第四档时租与递减日租本就冲突，原规则正确拒绝；成功恢复用例改用合法基价，冲突拒绝仍由既有及新测试覆盖。
- 浏览器曾有启动阶段临时失败，最终完整重跑正常退出0；没有修改浏览器/系统安全配置、终止用户浏览器或用强制成功退出掩盖断言。
- 最终失败项：无。

## 本地运行与剩余风险

- 发现并退出了已确认属于本项目的残留旧H5进程，由原 `com.renttask.h5.local` LaunchAgent重启接管；未修改启动配置或创建第二套服务，最终单监听且健康检查成功。
- 工作区原有主库运行态改动保留；没有通过测试修改真实用户配置、平台价格或生产数据库。
- 模式发生变化时采取安全失败，沿用原30分钟退避，直到下一轮重新计算；不会为了实时改价跳过安全校验。
- 平台动态上下限和真实授权状态仍在实际发布前验证，自动化不替代真实渠道上线观察；仅日租商品不启用时租。
- 旧页面不会覆盖自定义时租倍率，但需要刷新加载新资源后才能编辑它。前端资源版本已更新。
- 回滚前应先将自定义hour恢复为1并确认同步，或关闭相关自动调价；仅回滚旧代码不会自动撤销已下发价格。
- 本轮未提交、未发布生产；生产发布须另行授权。
