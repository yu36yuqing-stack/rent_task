# 订单账号搜索验收报告

日期：2026-11-15（Asia/Shanghai）。结论：实现及本地验收通过，未发布生产。

文案补充验收：订单汇总按用户要求改为“总计XX笔（0收入占XX笔）”，租赁中金额简化为“预计收入¥XX.XX”；仅调整文案，沿用现有统计字段及订单金额估算口径。订单脚本版本更新为 `20261115d`；JavaScript语法、零金额与非零金额实际渲染检查、12组手机/桌面与四游戏浏览器验收、差异检查及本地重启后 `/api/ping` 均通过。

## 实现范围

- 订单页增加一行搜索表单，位于时间快捷筛选下、汇总上。名字包含匹配，QQ/游戏账号完整匹配；搜索和清空回第一页，保留游戏、状态和时间筛选。
- 名称覆盖当前悠悠备注、账号备注及订单中仍保存的名称。只回填了QQ/游戏账号的名称字段不会绕过完整账号匹配规则。删除商品后可通过订单保留名称或账号查历史订单。
- 查询只读当前用户已同步订单，当前名称通过游戏和账号二元身份关联；名称候选采用单个JSON绑定参数，1201候选也不截断、不超过SQLite参数数量限制。
- 服务端时间范围只允许当日、近24小时、近7天、近30天，其他值回当日；忽略伪造起止日期参数。近30天沿用06:00业务日、租期交集定义，最多连续30个业务日，不提供全历史查询。
- 名称的 `%`、`_`、反斜杠按字面匹配，参数全部绑定；关键词去空白，最多64个Unicode字符，超限或含控制字符返回400。
- 列表、总数及统计一致追加关键词。原有统计字段自身的状态/当日口径保留，不把所有统计重定义为当前状态分页的计数。
- 前端区分草稿与已提交关键词，输入不请求；请求序号、筛选指纹和登录会话隔离旧结果。查询失败保留上次结果并明确提示；注销或换用户清空搜索与订单快照。
- 登录刷新按会话共享，搜索词改变不会使有效登录刷新失效。旧401或旧刷新结果不能注销或覆盖新用户。
- 没有新增表、索引或迁移，没有调用生产平台写接口。
