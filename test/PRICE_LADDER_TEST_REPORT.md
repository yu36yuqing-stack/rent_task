# 账号阶梯定价与渠道价格结果测试报告

## 1. 测试范围

- 账号级四档价格规则的新增、读取、更新与并发版本校验。
- 用户级自动阶梯调价总开关默认关闭，关闭时订单 Job 不加载阶梯执行模块。
- 总开关重新开启后，对已有配置执行一次校准；同档账号不调用渠道接口。
- 未配置账号不创建运行态、不参与日切重置和失败重试，也不调用渠道接口。
- 已配置账号支持四档全部清空回到“待配置”，同步停用规则、运行态和套餐基准。
- 清空配置不改变渠道当前价格，历史发布和错误日志继续保留。
- 全局配置不保存渠道字段，一期页面明确标注仅 U号租生效。
- 账号归属、游戏归属、已售账号过滤和非法价格校验。
- 从同游戏已配置账号复制四档价格，再手工修改后保存。
- 调价单量独立使用 `06:00～次日06:00` 内的 `已完成 + 部分完成` 订单，不修改钉钉图标口径。
- H5 未登录拦截、查询接口、保存接口和版本冲突响应。
- 当前游戏内按账号名称或账号数字即时搜索，并显示筛选数量。
- 桌面与手机端页面布局、编辑/保存状态切换、纵向滚动及横向溢出。
- 通用账号卡片与渠道特有套餐解耦，U号租、租号玩、悠悠租号使用同一渠道入口。
- U号租首次保存时自动记录内部套餐比例，并按账号自身比例计算四档套餐结果。
- 前台不展示内部基准，也不提供手工覆盖基准入口；套餐缺失时阻断发布。
- U号租价格设置失败日志按账号查询，只展示必要价格和错误信息。
- U号租低层改价接口不再套用旧固定公式，明确提交的套餐价格不会被覆盖。
- 发布服务按改价前套餐比例计算完整价格、保持押金，并记录平台拒绝和套餐缺失。
- 现有 5 分钟订单同步发现进入或退出完成态的订单，只对受影响账号重算档位。
- 目标档位与逻辑已应用档位相同时不调用 U号租，包括渠道 App 手工改价后的场景。
- 冷却期、U号租异常状态及渠道人脸异常不再阻止改价；在租订单和其他黑名单仍保留门禁。
- 业务日切换在每天 06:00 后首次订单同步时只入队一次，需要时恢复第 1 档。
- U号租账号级发布使用完整套餐目标价，成功后回读四个套餐并更新逻辑档位。

本轮不包含生产发布。

## 2. 测试环境

- Node.js 项目本地环境。
- SQLite 临时隔离数据库，不读取或修改生产数据。
- Google Chrome Headless，桌面视口 `1365x900`，手机视口 `390x640`。
- 本地 H5：`http://127.0.0.1:8080`，`/api/ping` 健康检查。

## 7. 剩余风险

- 渠道暂无订单推送，价格换档的发现时延取决于现有 5 分钟订单同步；06:00 重置在首个同步周期执行。
- 页面“当前渠道价格”来自最近一次商品同步快照，不是每次打开时实时请求 U号租；界面已明确标注“最近同步”。
- U号租准确的套餐上下限规则仍未知；平台拒绝会记录完整目标价格和错误信息，后续依据日志完善提交前校验。
- 分支覆盖率低于行覆盖率，主要是数据库底层异常回调和防御性空值分支；关键业务异常路径已覆盖。
