# 三渠道套餐比例与租号王改价测试报告

## 测试范围

- 阶梯定价继续只维护一份四档时租基础价。
- U号租、租号王、悠悠租号分别维护各自的套餐倍率。
- 套餐倍率保存后不立即调用渠道，而是将受影响账号加入待同步队列；下次价格同步时读取最新倍率。
- 租号王改价前查询 `getPriceTemplate`，根据模板识别仅日租、仅时租或时租与日租并存，并保留未由本系统配置的模板字段。
- 租号王优先使用账号列表已保存的 `dataId`；失效或缺失时按账号与游戏刷新一次后重试。

## 测试环境

- 日期：2026-09-21
- Node.js：24.13.0
- 数据库：临时 SQLite 数据库与迁移测试库
- 渠道请求：全部使用模拟响应和桩函数，没有向生产渠道提交改价

## 风险与上线建议

- 自动化测试没有执行真实渠道写操作。首次在生产环境启用租号王时，建议先选择一个测试账号，核对渠道实际返回字段与请求头兼容性，再逐步扩大范围。
- 租号王当前只支持自主定价模板；若账号切换为智能定价，系统会停止改价并记录明确错误，不会覆盖其模板。
- 套餐倍率属于用户级配置。保存后只影响后续同步，符合“一次设置、以后按最新比例衍生价格”的约定。
