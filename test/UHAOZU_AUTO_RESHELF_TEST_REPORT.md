## 实际改动

1. 新增主库 `system_config` 及迁移 `20261104_022`，包含有效 key 唯一约束、JSON约束和版本；只在 key 从未出现时初始化一条 `uhaozu.auto_reshelf_reasons` 配置。
2. 通用DB层支持查询、列表、保存及逻辑删除，保存用 `id + version` 校验；JSON空值、false、0均与配置缺失区分，读取不建表或补写默认。
3. 新增恢复策略模块，名单内默认三类原因：检测游戏在线、账号人脸识别、商品开启禁玩自动下架。归一空白、逗号及末尾冒号，保留受名单控制的旧在线检测兼容识别。
4. 流水线每轮获取一份不可变配置快照，人脸来源收敛和动作规划共用同一对象；动作记录附原始原因和配置ID、版本。
5. 命中原因进入已有普通上架/原价重新提交配置分支；黑名单、出租和渠道限制优先。
6. 已存在的 U号租人脸证据按配置撤销；其他渠道原有12小时窗口、来源不明证据、人工维护、订单冷却及已有人工抑制标记保留。配置释放不创建永久人工抑制标记。
7. 新增管理员 `scripts/system_config.js`，提供 `list/get/set`，写前导出0600权限旧值备份，冲突明确失败。
8. 修改两项既有动作回归和流水线阶段测试；补充DB、CLI、策略、人脸、动作及流水线异常回归；登记测试和覆盖率命令，更新 `product/PRODUCT_PRD.md`。
