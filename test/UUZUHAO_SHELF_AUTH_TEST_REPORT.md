# 悠悠上架授权异常暂停测试报告

日期：2026-10-23。

## 实现范围

- 上架接口返回 `12115014`（授权与账号密码不符）、`12115012`（授权失效）时，复用 `user_game_account.uuzuhao_auth_state`，保存 `required=true`、实际错误码和对应原因，不新增表、字段或迁移。
- 策略生成时不再生成已标记账号的悠悠自动补上架动作；已排队动作在请求前再检查一次。跳过记录为 `waiting_authorization`，不反复记录为新的接口失败。
- 严格按用户、游戏、账号隔离；不改实际上下架状态、黑名单、价格或手工风控开关，不阻断其他渠道、悠悠下架、商品及订单同步。
- 复用现有后台在线停查与风控等待逻辑。online 请求成功或失败均不能清除/覆盖上架授权标记；此约束在数据库事务内生效，防止并发检查后误清除。
- 仅新的成功商品同步明确确认正常上架或出租、商品ID存在且不带授权异常时，才能清除上架授权标记。普通下架、未知状态、缺失商品、失败同步及早于失败请求发起的同步均不能解除。
- 原 online QQ鉴权/商品不存在错误仍按原手工真实查询成功恢复，不由商品同步清除。
- 商品卡片沿用现有授权状态组件，显示具体上架授权原因，不误提示QQ鉴权失败或点击状态查询即可恢复；原档位、时租价与其他渠道展示不变。
- 不按历史日志批量给实际账号打标，不处理租号王限制、异常游戏映射或定价问题。

## 失败项与处理

- 第一轮扩展动作回归因全新临时库首次并行建表/连接初始化触发SQLite竞争而退出。已在测试夹具中按真实服务启动顺序预先初始化账号表和动作历史表，未修改生产SQLite设置；完整覆盖率回归和额外3次重复执行均通过。
- 测试中的busy、平台限制、渠道超时等输出属于有断言的异常注入，不是生产观测结果。最终无未解决测试失败。

## 剩余风险、发布与回滚

- 未真实调用生产上架接口验证平台当前业务行为，也未发布生产；当前真实账号不会因本地测试被批量打标。
- 上线后由下一次真实上架失败实时打标；已标记商品需号主在悠悠重新授权并恢复正常上架/出租，再由成功商品同步解除。仅在平台修改密码但仍保持下架，不会自动解除。
- 商品同步失败时保留标记；数据库写失败显式报错，不假装已保存。旧模块仍有未覆盖分支，尤其商品同步中的其他平台/历史兼容路径，详见HTML报告。

- 代码回滚可回到发布前版本；保留既有标记JSON，不删除或批量清理授权状态。
