# ZHW 商品同步价格保护测试报告

日期：2026-10-02。结果：通过。仅本地实现，未发布生产。

## 1. 改动范围

- `product/product.js`：仅 ZHW 商品快照组装与写入前合并增加价格保护。拉取完成后按用户批量读取旧快照，以游戏、账号匹配，再校验新旧商品ID。
- `product/zuhaowang_price_snapshot.js`：独立、无数据库/API副作用的价格字段选择与合并逻辑。
- 同一商品：缺失、空、非数值、零、负数、非有限数不覆盖旧有效价格；有效新价格允许涨价、降价；价格别名统一归一。
- 仅保留时租、24/72/168小时套餐价格及缺失的定价模式字段，不保留旧名称、状态、异常原因等其他事实。
- 切成 `day_only` 时，商品同步保留已有时租基价，不因为新时租字段为零而删除。
- 商品ID变化或身份无法确认时不继承旧价。新商品无价格仍保持未知，不从配置、运行签名或历史日志伪造价格。
- 不修改通用数据库合并、其他渠道同步或日租改价流程；不新增表、迁移、渠道API请求或生产补采。
- npm 新增 `test:zuhaowang-product-price`、`coverage:zuhaowang-product-price`。

## 2. 环境与用例

环境：本机 macOS、Node.js、SQLite、c8。新增集成测试使用临时目录下五个独立数据库，商品列表和改价/回读均为 fixture，不调用生产写接口。

核心完整回归：真实改价 Service 使用模拟渠道响应完成前查询、改价、回读确认，写入真实临时数据库；随后通过真实商品同步入口重复同步，验证快照仍有价格，并通过商品定价摘要 Service 验证当前档位、时租价可展示。

用例包括：

- 无价格同步保留已回读价格、重复同步幂等。
- 有效新价格、涨价/降价、字符串数值及别名归一。
- 缺失、null、空白、非法字符串、零、负值、Infinity、NaN、布尔值、数组和对象不破坏旧有效价。
- 商品ID更换不继承旧价；新商品缺价不虚构价格。
- 日租模式同步保留时租基价，同时更新有效日租价格。
- 清空旧异常原因，更新上下架、备注和角色名，不保护旧风险状态。
- 同账号跨用户、跨游戏隔离；非ZHW渠道数据不变。
- API失败不覆盖快照；旧快照读取失败则在写入前终止，避免无价覆盖。
- 手工删除账号不被同步恢复；停用渠道不拉取、不写入。
- 同步不新增模板查询、改价调用或价格发布日志。
